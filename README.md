# Test Automation Framework

## Description
This framework is designed for API testing with integrated functionality for web services automation. It uses **Java**, **Selenium**, **Rest Assured**, **Cucumber**, and **Maven** for clean, modular, and extensible test automation.

The framework supports:
- Automated generation of Step Definitions based on Gherkin keywords (`endpoint`,`URL`,`URI`, `GET`, `response body`, `status code`).
- A **File Watcher** that dynamically detects new Gherkin `feature` files and creates corresponding Step Definition files (if missing).
- Simple Maven-based testing execution.

### Automatic Step Definition Generation
- New Cucumber `.feature` files are detected using the **Feature File Watcher** component.
- If an unregistered step is found, it generates a new Step Definitions file automatically.

## StepDefinitionGenerator - Supported Keywords for Auto-Generated Code

The **StepDefinitionGenerator** automatically generates step definitions based on specific keywords found in the `.feature` files. For each keyword, the generator implements code logic tailored to the type of step. Below is the list of keywords supported for auto-generation:

### Supported Keywords and Auto-Generated Logic

1. **Endpoint, URL, or URI**
    - If the step contains any of these keywords (`endpoint`, `url`, `uri`), the generator will:
        - Handle setting the endpoint for HTTP requests based on configuration.
        - Automatically set up base URLs, paths, and IDs (e.g., `with id` logic).
        - Example Gherkin step:
          ```gherkin
          Given I set endpoint "posts.endpoint"
          ```

2. **GET Request**
    - If the step contains the keyword `get request`, the generator will:
        - Issue a GET request using Rest Assured.
        - Log the request and response details.
        - Example Gherkin step:
          ```gherkin
          When I make GET request
          ```

3. **Status Code**
    - If the step contains the keyword `status code`, the generator will:
        - Validate the response status code.
        - Log detailed status code assertions in the report.
        - Example Gherkin step:
          ```gherkin
          Then the response status code should be 200
          ```

4. **Response Body**
    - If the step contains the keyword `response body`, the generator will:
        - Validate that the response body contains the expected value or field.
        - Example Gherkin step:
          ```gherkin
          Then the response body should contain "username"
          ```

---

### How It Works
- The **StepDefinitionGenerator** scans the `.feature` files for these keywords during the auto-generation process.
- If a step is matched with any of these keywords, the generator creates a step definition method with the corresponding logic.
- The following aspects of the code are supported:
    - HTTP endpoint management and parameterization.
    - REST API request and response handling.
    - Automated validations and logging of test steps.
